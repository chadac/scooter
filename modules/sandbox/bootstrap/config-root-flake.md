# config/root — the real-system flake kubenix builds into the warmed PVC

DESIGN BOILERPLATE (interface sketch, not built yet). Stage: Design.

`/etc/scooter/config/` is a self-contained flake, produced by KUBENIX and materialized into
the warmed PVC upper by the warm Job. Its `flake.nix` composes the REAL sandbox system
(everything the bootstrap image dropped) and imports the agent's `./custom`.

## Layout in the PVC upper
```
/etc/scooter/config/
  flake.nix            # kubenix-generated; pins nixpkgs (flake lock), builds the toplevel
  flake.lock
  root/                # the real modules (== today's modules/sandbox-os/*.nix set):
    default.nix        #   nix-config, lazy-tools, web-services, marimo, carry-over,
    web-services.nix   #   sample-service, broker/local/registry-modules, dbus, …
    ...
  custom/              # MOUNTED from the workspace PVC (agent-editable); flake imports it.
    default.nix        #   agent-authored NixOS module(s); empty/no-op by default.
```

## flake.nix shape (generated by kubenix)
```nix
{
  inputs.nixpkgs.url = "github:NixOS/nixpkgs/<pinned-rev>";   # the version the image tracks
  outputs = { self, nixpkgs }: {
    # The toplevel the firstboot switch targets. Container PID 1 + overlay already set by
    # the bootstrap that's running; this layers the REAL system on top.
    sandboxSystem = nixpkgs.lib.nixosSystem {
      modules = [
        ./root                         # the real config (was modules/sandbox-os)
        { boot.isContainer = true; }
        # custom layered ON TOP (base = root; agent extends/overrides, can't break base).
        (if builtins.pathExists ./custom then ./custom else { })
      ];
    };
  };
}
```

## How it's produced (VolumeSnapshots stay)
1. kubenix renders `config/root` (the real modules) + `flake.nix` from the platform config
   (webServices/marimo/etc. options → the root modules). This is the ONLY place the real
   system is defined now.
2. The warm Job (warm-store-controller) boots the BOOTSTRAP image against a fresh PVC, drops
   `config/root` + builds `sandboxSystem` (the real toplevel + closure) into the upper.
3. Snapshot the PVC → the golden VolumeSnapshot.
4. Each conversation's `scooter-rw` upper CLONES that snapshot (#264 overlayDataSource) → the
   pod boots with config/root + the prebuilt closure present → firstboot switches instantly.

## Open IMPL questions
- kubenix generator: a new module that emits the `config/root` tree + flake.nix from the
  existing `agentSandbox` options (reuse the platform's webServices/marimo/etc. wiring).
- The warm Job today builds a `goldenExpr` string; here it builds `path:<config>#sandboxSystem`.
  Extend warm-store goldenExpr semantics OR add a dedicated golden-system Job.
- custom mount: provisioner binds workspace-PVC `.scooter/custom` → `config/custom` (subPath).
- nixpkgs pin: the flake lock in config/root is the version knob (the bootstrap image itself
  carries no nixpkgs; the real closure is in the snapshot). Bumping nixpkgs = re-warm + re-snap.
